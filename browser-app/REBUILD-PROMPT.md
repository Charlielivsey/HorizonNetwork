## 1. Platform and project facts

- **Builds:** `.github/workflows/hn-browser.yml` runs the tests, builds the Mac `.dmg` and `.zip` and the Windows NSIS `.exe` with electron-builder, then publishes a GitHub *preview* release tagged `browser-vX.Y.Z-<run number>`.

  - GitHub refuses "latest" releases from Actions with a 403, so the releases must stay *preview* releases.
  - Keep this pipeline working and keep the asset names (`HN-Browser-<version>-mac-arm64.zip`, `.dmg`, `HN-Browser-<version>-win-x64.exe`).
- **Build number:** `src/build.json` holds `{build: <GitHub run number>}`, written by CI.
- **Brand assets:**

  - App icons are generated by `npm run icons` (`scripts/icons.cjs`).

## 3. Animations: fluid and nice, everywhere

- **Motion style:** use spring-like or `cubic-bezier(.2,.8,.2,1)` motion, typically 150–320 ms. Panels and menus scale and fade from where they were opened. Full-page screens rise and fade. Lists stagger in subtly. Tabs open, close and reorder smoothly. Button presses compress slightly. Hover states ease. Progress bars glide.
- **Only animate `transform` and `opacity`** (and `clip-path` where it's cheap). Never animate `width`, `height`, `top`/`left`, `box-shadow`, `filter: blur()` or `background-position` every frame. Never use `backdrop-filter` blur over large areas; it was a real source of lag.
- **No endless animations that repaint the toolbar.** Pulsing dots should pulse a few times and stop, or use compositor-only transforms. The loading indicator must use transforms.
- **Smooth across processes.** Opening a menu, switching tabs, switching themes, typing in the address bar and closing panels must never stall, flicker, or show a frozen picture of the page.
- **Reduce motion:** respect the "Reduce motion" setting and the system's `prefers-reduced-motion`. Every animation must have a reduced or instant version.
- **Measure it:** check performance with Chromium's tracing or DevTools Performance panel. There should be no long tasks above 50 ms during these interactions.

## 4. Theme switching must be flawless

Today it is "dodgy". The causes:

- The interface is drawn by more than one page: the shell, a transparent overlay and a suggestions popup. Each changes theme separately.
- The theme change uses a View Transition circle reveal, which takes a screenshot of the page.
- Each HN website tab gets its CSS removed and re-inserted (`site-theme.cjs`).
- The native title-bar colours change separately.

Requirements:

1. **Everything changes together, in one frame.** Theme everything with CSS custom properties. Every trusted UI page applies the same theme in the same frame, driven by one state update.
2. **A clean, consistent animation.** Either a smooth colour crossfade done with CSS transitions on custom properties, or no animation. No screenshot-based reveal that can tear.
3. **Website tabs update without flashing.** For HN Group website tabs that opt in to browser themes (the `hnThemes` setting), insert the new theme CSS *before* removing the old one, so there is never an unstyled frame. Do not reload the page, and never lose what the user typed in forms (there is a test for this).
4. **The native title bar matches:** `nativeTheme.themeSource`, Windows `setTitleBarOverlay` colours and the window background colour all update in the same step.
5. **Settings are saved** to `preferences.json` once, without blocking the UI.

## 5. Architecture to build (from scratch)

- **Main process** (`src/main.cjs` plus focused modules). It owns the window, tabs (`WebContentsView`), sessions, permissions, downloads, the account, the VPN, SSH, updates and settings. Remote websites run with `sandbox:true`, `contextIsolation:true`, `nodeIntegration:false` and `webSecurity:true`, in the `persist:hn-browser-pages` partition.
- **Trusted UI pages** are local files with a strict CSP (`script-src 'self'`, no inline script) and a preload exposing a small, frozen `window.browser` API.
  - Every IPC handler must check that the sender is one of the browser's own UI web contents, at its exact URL and main frame. Visited websites must never reach browser controls or tokens.
- **Menus over the live page.** Because tab views are drawn above the window's own page, menus and popups cannot be HTML inside the toolbar page. Draw them in a trusted transparent `WebContentsView` laid over the page; today this is `ui/shell.html?layer=overlay`. Never capture or detach the page to fake an overlay: that was the old source of lag and frozen pages. Keep the window's own web contents as the toolbar so window dragging (`-webkit-app-region: drag`) keeps working on Mac and Windows.
- **One state object, batched.** Send state to the UI at most once per frame, and never resend large data (profile picture, tab icons) unless it changed.
- **Focus rules:**
  - While a menu or the PIN screen is open, keyboard focus stays in it. A loading tab must not steal focus; re-focus after Chromium's focus change settles.
  - Closing a menu returns focus to whatever opened it.
- **Toast messages** ("Bookmarked", errors) must be visible above the page, and never hidden behind it.
- **Keyboard shortcuts work** whether focus is in a page or in the browser UI (handle them in `before-input-event` for every web contents):
  - Tabs: Cmd/Ctrl+T, W, Shift+T (reopen closed tab), Ctrl+Tab and Ctrl+Shift+Tab, Cmd/Ctrl+1–9.
  - Page: Cmd/Ctrl+L, R, F5, F (find), D (bookmark), P (print), back and forward (Cmd+[ and ] on Mac, Alt+←/→ on Windows), zoom (+, −, 0).
  - Screens: Cmd/Ctrl+, (Settings), J (Downloads), Y or H (History), Shift+O (Bookmarks), Shift+V (VPN), Shift+L (lock).
  - Escape closes menus. A second Escape in the address bar restores the page address.
- **Single-instance lock:** opening the app again focuses the existing window.

## 6. Features that must all survive the rebuild

**Account (HN Group Auth)**

- **Sign-in:** the public native client `browser` signs in with S256 PKCE and a one-use loopback callback (`http://127.0.0.1:<port>/callback`). It calls `https://auth.hngroup.org.uk/api/native/*` (`exchange`, `logout`, `profile`, unlock and refresh routes; see `src/sign-in.cjs`, `auth-site/native.js` and `staff-portal/lib/resume.js`). Never embed a server secret.
- **Remembered account:** remember the last account across restarts, storing **only** the revocable browser credential with Electron `safeStorage` (Keychain or DPAPI). There is no plaintext fallback, and passwords and PINs are never stored.
- **PIN screen:** every launch opens straight on a masked six-box PIN screen. Six digits verify automatically, once. Wrong PINs shake, and they share a five-attempt limit with websites. The screen also offers "Use another account" and "Forget".
- **Lock:** a lock command, auto-lock after idle (off/5/15/30/60 minutes), and an option to lock on sleep or screen lock.
- **Website sign-in:** an unlocked browser offers its account to top-level HN Auth pages through a 60-second, single-use, request-bound header ticket (`src/auth-headers.cjs`). Auth still asks for the PIN and enforces each website's permissions.
- **Profile editing in Settings:**
  - It uses the in-memory unlock key, which is never stored and is cleared on lock. Only the person's own editable fields can change: display name, phone, location, time zone, skills, languages, bio (with "show on website"), birthday, status (Available/Busy/Away/Out of office with a message and an end time) and profile photo (JPG/PNG/WebP cropped to a square, or a GIF up to 1.4 MB).
  - Animated GIF avatars must animate everywhere they appear.
  - It goes through Auth `/api/native/account`, `/account/update`, `/account/status` and `/account/photo`.

**Browsing**

- **Tabs:** pin, mute, duplicate, reload, close others, close to the right, reopen closed, and tab favicons. Favicons are fetched in the main process: images only, at most 200 KB, sent to the UI as data URLs.
- **Address bar:** it recognises HN company and service names and common one-character typos (`src/sites.cjs`, e.g. "staff portak" → staff portal). Other text becomes a search with the chosen engine (Google, Bing or DuckDuckGo), and explicit URLs are kept. Only `http` and `https` can be opened.
- **Suggestions:** an HN shortcut, bookmarks and history, with arrow-key selection. Drawn above the live page with no flicker while typing.
- **Find in page:** a floating box at the top right with match count, next and previous, and Escape to close.
- **Pages:** zoom with a per-tab indicator and a default zoom setting, print, a page right-click menu (open link in new tab, copy link, image actions, edit actions, search for the selection), a pop-up blocker setting, and permission prompts. Pages can ask for camera or microphone, location, notifications and clipboard write. These are allowed once on HTTPS, for the active tab only.
- **HN themes on HN websites:** the setting that applies the browser theme to HN Group websites, via `site-theme.cjs` with its eligibility rules.
- **History and bookmarks:** stored on this device only (`src/library.cjs`). History has search, removal and clearing (last hour, day, 7 days or all time). Bookmarks can be renamed, reordered and removed; Cmd/Ctrl+D toggles a bookmark.
- **Start-up:** a new tab, or "Continue where you left off" (restore tabs). Tabs are always restored once after an update (`restore-once`).

**Downloads**

- **Manager:** a themed downloads manager with progress and speed, pause/resume, cancel/retry, show in folder, open (with confirmation), remove from list, clear finished, search and filter. History is kept, and interrupted downloads offer retry after a restart.
- **Settings:** ask where to save, a default folder, notify when complete, and open the manager when a download starts. Clearing history never deletes files.

**Updates**

- **Checking:** check `https://downloads.hngroup.org.uk/api/releases` at start-up (after 15 seconds) and every 6 hours, and compare `version-build`.
- **In-place install (keep it, no DMG):**
  - **Mac:** download the `mac-arm64-zip`, verify its size and SHA-256 twice, then the bundle id `uk.org.hngroup.browser`, its version and `codesign`. Swap it for the running app after it quits (an admin prompt only if needed) and reopen it (`src/installer.cjs`).
  - **Windows:** run the verified NSIS installer silently (`/S --force-run`).
- **About & updates screen:** shows the version, build, progress and "Restart to update".

**Settings that exist today (keep them all)**

- **Settings list:** theme, `hnThemes`, `homeButton`, `reduceMotion`, `defaultZoom`, `greeting`, `recentSites`, `startup`, `confirmClose` (when closing several tabs), `newTabNextToCurrent`, `popups`, `searchEngine`, `suggestions`, `saveHistory`, `askDownload`, `downloadPath`, `downloadNotify`, `openDownloadsOnStart`, `autoLock`, `lockOnSleep`, `vpnAutoConnect`.
- **Other Settings sections:** clear cache, clear cookies and site data, reset settings, a keyboard shortcuts list, and About (Chromium/Electron versions).
- **Validation and old settings:** validate every setting in `src/settings.cjs`. Old `preferences.json` files must load, ignoring unknown keys such as the removed `bookmarkBar`.

## 7. HN VPN: make it work well

- **Server side:** HN Group's WireGuard VPN runs on the VPS.
  - Interface `wg-hn`, UDP 51820, server address `10.88.0.1` / `fd88:88::1`, clients in `10.88.0.0/24`.
  - It is a **full tunnel**: client `AllowedIPs = 0.0.0.0/0, ::/0` and `DNS = 1.1.1.1, 1.0.0.1` (`configVersion` 3).
  - The service is `https://vpn.hngroup.org.uk` (`vpn-site/`). Read its `server.js`, `lib/auth.js` and tests.
- **The browser's VPN** (`src/vpn.cjs`):
  - **Sign-in:** an app sign-in through a browser tab. Open `/auth/login?app=<sha256 hex challenge>&loopback=<port>`. The one-time code comes back to `http://127.0.0.1:<port>/vpn-callback`, and the browser swaps it with its secret at `/api/app/exchange`. Requests carry `X-HN-VPN-Client: hn-browser` and `X-HN-VPN-App: <version>`.
  - **Storage:** store only the encrypted VPN token (`vpn.enc` via `safeStorage`).
  - **Registering this computer:** make the WireGuard key pair locally, send only the public key to `POST /api/devices`, and write the private key straight into the local config. Each account can have at most 5 devices. Setting up again replaces this computer's device instead of adding another.
  - **Mac control:** use the same root helper as the HN Secure Network Mac app (`/usr/local/libexec/hn-vpn/hn-vpn-ctl`, installed once with an admin prompt, plus a sudoers rule for that helper only), using Homebrew `wireguard-tools`.
    - `browser-app/src/hn-vpn-ctl` must stay byte-identical to `mac-vpn-app/Resources/hn-vpn-ctl`, so the two apps share one connection.
  - **Windows control:** use the WireGuard for Windows tunnel service `WireGuardTunnel$hn-vpn`.
    - The config lives in an Administrators-only ProgramData folder.
    - The service ACL lets interactive users start and stop it, so connecting doesn't prompt every time.
  - **Account rules:** set-up, connecting and VPN sign-in require the unlocked HN account. Signing in to the browser as a different HN account signs the VPN out.
- **Make it work well:**
  - **Status:**
    - Show the true connection state, polled every 15 seconds and reconciled with the OS. Detect a tunnel already brought up by HN Secure Network.
    - Show the public IP the internet sees (`GET /api/ip` returns `{ip, viaVpn}`), whether the server answers, and the last handshake time.
  - **Clear guided set-up:** sign in → install WireGuard (open Terminal with `brew install wireguard-tools` on Mac, or the WireGuard download page on Windows, with a "check again" step) → set up this computer → connect.
  - **Updating old devices:** devices set up for the old split tunnel get an "Update this computer's VPN" step.
  - **Error messages that say what to do.** For example: when no handshake happens after connecting, explain that UDP 51820 may be blocked. Also cover: wrong password at the admin prompt, WireGuard missing, the device removed on the website, and the account disabled.
  - **Connect and disconnect** from the toolbar button with a clear on/off state, "auto-connect when unlocked", "remove this computer" and "manage devices on the website".
  - **Test the Windows path on a real PC.** CI has no WireGuard service, so cover it with unit tests of the generated PowerShell and ACL, and say clearly what you couldn't test.

## 8. New: SSH into the VPS from the browser

Add a built-in SSH terminal for the HN Group server.

- **Where:** an "SSH" item in the VPN panel and the main menu, and a shortcut (for example Cmd/Ctrl+Shift+S). It opens an SSH screen or tab inside the browser, styled like the rest of the UI.
- **Connection:** connect to `10.88.0.1` port 22 **through the HN VPN**. If the VPN is off, offer to connect it first, then wait until the server answers.
- **Implementation:** use the `ssh2` npm package in the main process and `xterm.js` (with the fit and web-links add-ons) in a trusted UI page. Support resizing, copy and paste, scrollback, themed colours that follow the browser theme, and several sessions as tabs.
- **Credentials:** the username defaults to `root` and is remembered. Ask only for the password, every time: send it straight to `ssh2` and **never store or log it**. Optionally support a private key file that the user picks, read only for that connection.
- **Host key:** on first connection, show the server's host-key fingerprint (SHA-256) and remember it after the user accepts. On later connections, refuse with a clear warning if it changes.
- **Timeouts and errors:** time out after 15 seconds with a helpful message ("The server isn't answering through the VPN. Check the VPN is connected and UDP 51820 is open."). Report wrong passwords and dropped connections clearly, with reconnect.
- **Security:**
  - Only this fixed server: there is no general SSH client and no custom hosts.
  - Remote websites can never reach any of this.
  - Requires the unlocked HN account and the VPN set up.
- **Tests:** include tests using a local `ssh2` test server, covering host-key pinning, a wrong password, timeouts and resizing.

## 9. Security rules (non-negotiable)

- **Website isolation:** visited websites run in sandboxed views, with no Node access and no access to browser IPC. Navigation is limited to `http`, `https` and the trusted `hn-browser://start/` new-tab page. Block `webview` attachment, `file:` and other schemes, and URLs with credentials in them.
- **Secrets:** nothing secret goes to the UI pages. State sent to the UI must never contain tokens. There is a test that checks the account token never appears in renderer state.
- **Storage:** passwords and PINs are never stored. Tokens are stored only with `safeStorage`.
- **Code:** no new dependencies without need, and pin exact versions. Keep `package-lock.json` in sync.
